# WarAxe Mobile — full-stack starter

Мобильный браузерный прототип + API-сервер. Игровой проект самостоятельный; закрытый код и чужие оригинальные игровые ресурсы WarAxe не копируются.

## Требования
- Node.js 20+
- Docker Desktop (для PostgreSQL) или отдельный PostgreSQL 16

## Установка
```bash
npm install
cp server/.env.example server/.env
docker compose up -d db
npm run db:generate
npm run db:migrate -- --name init
```

## Запуск
В первом терминале:
```bash
npm run server
```
Во втором:
```bash
npm run dev
```
Vite покажет адрес, обычно `http://localhost:5173`; API работает на `http://localhost:3001`. В интерфейсе нажми на имя персонажа сверху, чтобы открыть вход/регистрацию. После входа профиль, золото, здоровье, охота и получение награды задания используют API.

## API
- `GET /api/health`
- `POST /api/auth/register` `{ "email", "username", "password" }`
- `POST /api/auth/login` `{ "email", "password" }`
- `GET /api/me` — Bearer token
- `POST /api/game/hunt` `{ "enemy": "griffin" | "golem" | "abyss" }` — Bearer token
- `POST /api/game/claim-quest` `{ "questCode": "first_hunt" }` — Bearer token
- `POST /api/game/heal` — Bearer token
- Socket.IO: authenticated connection, event `chat:send`, event `chat:message`

## Важно
Это ранний серверный MVP: регистрация, персонаж, PostgreSQL-сохранение, серверная выдача наград, лечение, задания и чат. Перед публичным запуском нужны rate limiting, email verification, refresh-token rotation, аудит экономики, антибот-защита, миграции/бэкапы, мониторинг и нагрузочные тесты. PvP, гильдии, аукцион и полноценный live combat ещё предстоит разработать.

## Онлайн-системы 3.0
- `POST /api/arena/duel` `{ "opponent": "username" }`
- `GET /api/boss`, `POST /api/boss/attack`
- `GET /api/clans`, `POST /api/clans`, `POST /api/clans/join`
- `GET /api/auction`, `POST /api/auction/list`, `POST /api/auction/buy`

Все эти маршруты требуют Bearer-токен. Для использования нескольких аккаунтов зарегистрируй несколько игроков. Перед публичным запуском обязательно провести аудит PvP-формулы, защиту от мультиаккаунтов и стресс-тесты экономики.

## Автоматическая проверка в облаке (GitHub Actions)

В проект добавлен workflow `.github/workflows/ci.yml`. После загрузки проекта в GitHub он автоматически:

1. Устанавливает npm-зависимости на чистом Ubuntu runner.
2. Запускает статические smoke-проверки.
3. Проверяет Prisma schema и генерирует Prisma Client.
4. Собирает клиент и API-сервер.
5. Поднимает временный PostgreSQL 16, применяет схему через `prisma db push`.
6. Запускает API и проверяет `GET /api/health`.

Запуск: создать GitHub repository, загрузить в него содержимое проекта и открыть вкладку **Actions**. Workflow запускается автоматически на push и pull request; его можно запустить вручную через **Run workflow**. Это облачная CI-проверка; для запуска необходим доступ GitHub Actions к npm registry.

### Локальная проверка

```bash
npm install
cp server/.env.example server/.env
# Убедись, что DATABASE_URL в server/.env указывает на локальную PostgreSQL
# JWT_SECRET должен быть задан непустым значением

docker compose up -d db
npm run db:generate
npm run db:push
npm run test:static
npm run build
npm run server:build
```

В отдельном терминале запусти API и затем интеграционные тесты:

```bash
npm run server
# в другом терминале:
npm run test:integration
```

`db:push` подходит для локальной разработки и CI-песочницы. Для production следует использовать проверенные миграции Prisma, резервное копирование и процедуру отката.

**Статус этой поставки:** конфигурация и тестовые сценарии подготовлены, но полная сборка и интеграционный прогон в среде подготовки не подтверждены: доступ к npm registry не отвечал. Успешный запуск GitHub Actions будет первым подтверждением реальной сборки на чистом runner.
